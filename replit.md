# Synesthesia AI

## Overview

Synesthesia AI (formerly Sensory Canvas) is an assistive application designed for neurodivergent individuals to help manage sensory overload and improve social interaction. The application captures real-time audio and visual data through the device's camera and microphone, processes this information using AI, and provides adaptive filtering and recommendations based on the user's emotional state and biofeedback.

The system uses AI-powered emotion detection, sound source summarization, and stress-based filtering adjustments to create a personalized sensory experience. Journal entries track the user's state over time, storing emotion, ambient sounds, heart rate, filtering levels, and AI-generated recommendations.

## System Architecture

### Frontend Architecture

**Framework**: Next.js 15 with React 18, using the App Router and React Server Components (RSC) pattern. The application runs in dark mode by default.

**UI Component Library**: Radix UI primitives wrapped with custom shadcn/ui components for consistency. Components use a glassmorphism design pattern with backdrop blur effects and transparent backgrounds to create a calming visual experience.

**Styling**: Tailwind CSS with custom design tokens aligned to the app's calming aesthetic:
- Primary color: Soft purple (#A78BFA area)
- Secondary color: Soft lavender (#D1C4E9)
- Accent color: Pale rose (#F8BBD0)
- Background: Light gray (#F5F5F5)
- Typography System:
  - Playfair Display: Headings (h1-h3) - elegant serif
  - Inter: Body text and paragraphs - clean sans-serif (default)
  - Quicksand: Feature cards and UI elements
  - Poppins: Legacy body text
  - Nunito: Legacy headlines

**State Management**: React hooks for local state. Real-time data synchronization handled through Firebase Firestore listeners via custom hooks (`useDoc`, `useCollection`).

**Animation**: Framer Motion for smooth transitions and gentle animations to avoid overwhelming users. Predefined motion patterns in `lib/motion-patterns.ts` ensure consistent animation behavior.

**Enhancement Architecture** (November 2025):
All canvas page enhancements are implemented as standalone, plug-and-play components:
- **Components**: Located in `src/components/enhancements/` (DemoModeProvider, CameraControls, HelpModal, CalmingInterventionAlert, WellnessHistory, EmpathyChatbot)
- **Hooks**: Custom hooks in `src/hooks/` (useCameraSwitch for device switching, useOverwhelmDetection for distress monitoring)
- **Utilities**: Helper functions in `src/utils/` (exportJournalEntries for JSON download)
- **Design Pattern**: Enhancements wrap or overlay existing components without modifying core logic
- **Accessibility First**: All enhancements include proper ARIA attributes and keyboard navigation
- **Non-Breaking**: Each feature can be toggled or removed independently without affecting others
- **Safety-Focused**: Overwhelm detection and empathy chatbot provide proactive mental health support

### Backend Architecture

**Authentication**: Firebase Authentication with anonymous sign-in as the primary method. Non-blocking authentication pattern ensures the UI remains responsive during sign-in operations.

**Database**: Firebase Firestore for real-time data storage with a nested collection structure:
- `/users/{userId}/journalEntries/{entryId}` - Stores journal entries containing emotion, sound summary, heart rate, filtering level, and recommendations

**AI Processing**: Google Genkit framework with Google Gemini 2.5 Flash model for:
1. **Emotion Detection** (`detect-dominant-emotion`) - Analyzes facial expressions from camera input to identify emotions (happiness, sadness, anger, surprise, fear, disgust, neutral)
2. **Sound Summarization** (`summarize-sound-sources`) - Processes audio input to identify and summarize dominant ambient sounds
3. **Stress-Based Filtering** (`adjust-filtering-by-stress`) - Adjusts sensory filtering (0-10 scale) based on heart rate to reduce environmental clutter
4. **Recommendation Generation** (`generate-recommendation`) - Provides personalized, actionable recommendations based on emotion, sounds, heart rate, and user history patterns. The enhanced system:
   - Analyzes user journal history for emotional patterns and time-of-day trends
   - Tracks recommendation diversity to avoid repetition
   - Combines empathetic "help feel better" focus with pattern-aware suggestions
   - Uses ref-based data access to prevent infinite feedback loops
   - Includes fallback strategies for graceful degradation

All AI flows are server-side actions, invoked from client components through Next.js server actions pattern.

**Media Processing**: Client-side media capture using browser APIs:
- Camera/microphone access via `navigator.mediaDevices.getUserMedia()`
- Image snapshots captured from video stream using canvas element
- Audio recording via MediaRecorder API
- Base64 data URI encoding for AI processing

### Error Handling Strategy

**Firestore Permission Errors**: Custom error handling system using a typed event emitter pattern:
- `FirestorePermissionError` class provides detailed context about failed operations
- `errorEmitter` broadcasts permission errors globally
- `FirebaseErrorListener` component catches and throws errors to Next.js error boundaries
- Non-blocking write operations continue execution even if permissions fail

**Rationale**: This approach prevents UI blocking while still surfacing critical permission issues to users through error boundaries.

### Data Flow Pattern

1. User grants camera/microphone permissions
2. Client captures video/audio streams
3. Periodic snapshots sent to AI flows for analysis
4. AI results stored in Firestore journal entries
5. Real-time Firestore listeners update UI components
6. Filtering adjustments applied to video feed based on stress levels

**Non-Blocking Operations**: All Firestore writes use non-blocking pattern (`addDocumentNonBlocking`, `setDocumentNonBlocking`) to maintain UI responsiveness. Errors are handled through the global error emitter.
